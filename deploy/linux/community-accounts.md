# 账户找回、个人主页和社区投稿

登录页提供注册确认密码及邮箱找回。发送注册或找回验证码前，先通过绑定邮箱、用途和来源 IP 的六位数字图片校验。图片数字只以 PNG 像素返回，挑战保存于数据库，五分钟失效、最多五次尝试且成功后即消费。生成挑战和邮件发送均限制频率；邮件验证码十分钟有效，注册和找回用途互相隔离。只有测试应用返回调试数字，生产配置不得暴露验证码。

`POST /api/auth/reset-password` 校验注册邮箱的找回验证码和新密码确认，锁定用户行更新密码哈希，消费全部旧验证码并撤销该用户全部登录会话。登录、当前密码改密、邮箱找回锁定同一用户行。未注册邮箱的找回请求返回通用提示，不发邮件、不建立账号。Resend 密钥仍仅在服务器私有环境配置中。

个人主页 `/people/<用户ID>` 对所有访客开放，展示公开赛事的确认报名履历、正式作品及已发布内容。`GET /api/profiles/<用户ID>` 使用独立公开字段，不能复用包含邮箱或角色的账号序列化，也不返回报名表、邀请码、草稿或审核中的投稿。本人主页的“账户设置”页签显示邮箱与改密表单；公开概览不放置账户表单。旧 `/account` 地址跳转至 `/people/<用户ID>?tab=settings`。人物链接统一使用 `UserLink`，队伍成员、作者、评委、用户管理及榜单成员均按用户 ID 关联主页。

所有登录成员可从 `/contribute` 投稿文章（blog）或独立作品（work），正文使用现有 Markdown 编辑器并支持附件。作者只能保存草稿或提交审核，不能自行发布、变更归属或编辑他人投稿。组织者、编辑和管理员在 `/manage/content` 查看待审核数量、审核意见并发布或退回；作者修改已发布内容时立即下线，重新审核后公开。文章进入资讯，独立作品进入作品档案，均归入作者个人主页。作者自己的草稿和审核意见只在登录后的投稿管理中显示。

投稿附件使用 `scope=contribution` 上传，存储为 private。审核前只有上传者及内容管理员可读取；公开正文引用后才允许访客读取，撤回后再次隐藏。作者不得引用他人的私人附件；私人附件响应始终 `private, no-store`，避免权限改变后继续从 HTTP 缓存读取。原有非投稿 Markdown 附件的公开行为保持兼容。

迁移 `d1e6f8a92410` 在既有 `c4d7e2a91065` 后新增附件 visibility 和内容 review_note 两个字段，保留所有原有数据，原有附件默认 public。部署先执行正式备份，再升级数据库、切换应用并重启 API/web。公开个人主页沿用 Redis 匿名缓存；账号、投稿或报名变更提交后失效，认证请求绕过缓存。

专项行为测试位于 `tests/test_community_accounts.py`，覆盖验证码绑定、失效、重放、错误次数、邮件失败、生产不暴露数字、密码找回与会话撤销、注册确认、投稿权限与审核、私人附件以及公开履历隐私。历史迁移测试使用对应时期的最小实体，不向旧版内容表插入新版 ORM 字段。

社区界面采用独立的介绍/发布行、分类/搜索行和内容区，样式集中在 `app/community.css`，不改动全站页脚行为。个人主页主栏展示作品文章，侧栏展示参赛履历；手机单列排列。作品档案统一切换全部/参赛/社区，避免连续空列表；分享作品入口使用 `/contribute?kind=work` 预选作品类型。人物卡片的内容链接与作者链接保持同级，避免嵌套链接。

## 队伍自主测评与正式结果

队伍在题目提交页上传程序后主动点击“开始测试”，每次成功建立任务扣除本队本题的一次机会，执行题目设定的单次时间上限。同一队伍同一题只允许一个排队或运行中的任务；工作节点重试同一任务不再扣次数。测试不要求研究报告，也不覆盖已正式提交的内容或结果。测试任务保留独立程序副本，后续草稿修改、附件删除均不改变正在运行的程序。

测试历史只向本队和赛事管理者开放。队伍从已完成的测试中选择“用于正式提交”；正式提交校验归属、测评规则和程序 SHA256，保证实际提交的程序与测试程序一致。报告和说明可以完善，程序变更必须重新测试。正式提交不再建立任务或扣减测试次数，即使机会耗尽，也能提交已经完成且匹配的测试结果。

正式结果绑定保存在当前提交快照的 `evaluation_run_id`，队伍和评委均可查看该结果及逐场景指标。评委不能查看未选中的自主测试历史，匿名访客和其他队伍不能读取指标；公开作品材料仍遵循原有规则。旧正式测评记录保留兼容读取。
