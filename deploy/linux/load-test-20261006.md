# 300人并发访问检查（2026-10-06）

目标：https://uestcai.top；开始时间：2026-10-06T00:10:21+08:00。从独立测评节点通过公网HTTPS发起请求，网站节点为2核、1676MB内存，PostgreSQL与Redis同机；保留Nginx限流。

## 结论

首页300个请求同时开始，300/300返回200，P95约3.05秒。300个虚拟访客持续浏览时，出现765次429和2次502，因此不能认定300人完整业务流程已无错误通过。所有健康探针均返回200，没有超时、整站中断或systemd服务重启。

## 服务器与异常定位

服务器每2秒采样，整机CPU最高39.75%，可用内存最低917.3MB；Node RSS峰值161.5MB，swap始终约8MB。前后端MainPID保持不变，NRestarts均为0。测试后首页及题库API再次返回200。

429由同一个出口IP超过每秒30次API、burst=60的Nginx限流产生；未关闭保护或伪造来源IP。测评节点的既有轮询也共享此IP限额，测试时记录了轮询被限流，不能把当前结果解释为300个不同IP访问者的结果。

502均来自GET /api/problems，时间为北京时间00:11:13和00:11:25。Nginx日志为“Connection reset by peer”读取上游响应头失败；同一秒Gunicorn分别记录“Autorestarting worker after current request”、旧worker退出与新worker启动。配置为2进程×4线程，max-requests=1000、jitter=100。因此已定位到按请求数轮换期间的连接重置；主服务未崩溃。尚未修改生产配置或验证修复。

## 范围与后续

本次是HTTP并发读取：首页、赛事页、题库及公开JSON。未执行浏览器JavaScript，也未下载全套静态资源；未测登录、注册、报名、提交、上传、评审或Docker测评。300人浏览是有停留时间的300个虚拟用户，并非始终300个在途请求；最后的首页突发批次才是300个同步开始的HTTP请求。

优先处理Gunicorn轮换期间偶发502，再独立验证轮换；校园多人共享公网出口时，需要评估现有限流是否误伤正常访问。若要确认正式比赛容量，还需使用测试账号与隔离数据做报名/提交等业务流程测试，以及更长时间持续负载。
