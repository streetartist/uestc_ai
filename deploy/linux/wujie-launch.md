用户要求本轮暂不验收AI模型接口，不取消题目的API要求或开赛检查。生产网站的三个题目和三个公开开发ZIP均可访问；MC和机械臂的固定镜像摘要与独立Docker节点实际安装镜像一致，Docker服务、隔离网络和代理在线。两题各有三个固定私有场景。

第一题已绑定组织方内置数据镜像 `image-042030ef49` 和 `wujie-depth-v1` 清单摘要，启用classification-v1。新组织方实例从该镜像恢复后，470段测试数据、运行代码封存、RTX4080SUPER32GB与CUDA均通过检查，默认30GB系统盘使用约643MiB。新实例未挂载原构建机的备份文件存储，内置数据仍完整，证明运行不依赖原存储。

恢复后的镜像在隔离API验收中完成领取自测、冻结ZIP下载、470段真实输入的可信推理、指标回传、正式选择结果和本队/评委可见性；正式选择不多扣次数。本次恢复验收用随机初始化的接口模型，指标不是参赛成绩，也不代表模型质量。生产网站的实际工作端认证与镜像/数据广告另行验证通过；本届正式题目尚无提交，不能把隔离验收描述为真实参赛记录。

选手训练渠道已配置为 `image-82e8bfacc6`、`v-32g-p`、CUDA驱动下限12.8。用户授权估算额度后统一设置每队每题10GPU卡时（36,000卡秒）、16.8元参考运行费用上限，配置价格1.68元/卡时；实际租价变化时仍受费用上限约束。选手镜像在构建实例通过1,995训练/466验证样本的真实GPU训练与打包预测验收；选手镜像另在新建临时实例完成恢复验收：数据和运行代码校验通过，默认30GB系统盘使用约2.2GB；真实GPU训练一轮及8条40类预测通过。临时实例验证后立即关机并释放。AutoDL渠道认证已通过真实API读取检查。

新增 `uestc-ai-compute.service` 已在线，负责请求预占、额度控制、到时关机与恢复；启用监控本身不创建队伍实例。相关38项算力测试、6项开赛检查/计分测试和4项独立自测测试全部通过。保留每题3次机会、1800/3600/1800秒总时限、80/20和50/50评分规则。

组织方GPU实例为 `pro-7912ff659683`，自动调度复用此实例，不创建并行付费实例或借用队伍训练实例。工作端私有配置在该实例 `/etc/uestc-classification.env`（0600），令牌不在镜像或Git中。`uestc-ai-compute` 同时处理训练额度和独立的组织方测评池：有排队测试自动开机，可信工作端就绪后串行领取，空闲120秒确认关机。开机最长等待600秒，库存不足、认证拒绝或测评端未启动时，尚未执行的机会自动退回一次；已执行的选手程序错误或超时仍计次。比赛起止时间未设置，AI渠道按用户要求后续接入，开赛保护保持开启。

题目“环境与资源”显示 GPU 自动调度状态；管理员可登记已安装私有数据的专用实例、算力渠道、工作端标识，以及开机等待和空闲关机时长。API为 `PUT /api/manage/problems/<id>/judge`，仅管理员可修改。配置绑定保存于 PostgreSQL，与队伍训练卡时和费用独立。导入题目ZIP不迁移服务器专用实例、认证凭据或运行状态。

调度使用数据库租约；开机意图在调用 AutoDL 前提交，超时不重复开机，通过状态核对恢复；关机前持有池锁并检查排队/运行任务，领取任务也持有相同锁。新任务在关机过程中到达会等待关机完成后自动开机。启动侧车用文件锁限制单个可信进程；镜像、数据摘要、注册worker标识必须匹配。运行3小时后暂停领取并完成当前测试，再轮换启动；独立4小时关机命令防止网站完全不可用时无限计费。队伍历史显示等待开机、运行状态和已退回次数。

在网站服务器上启动组织方测评端，例如运行一小时：

```bash
/opt/uestc-ai/shared/venv/bin/python \
  /opt/uestc-ai/current/deploy/linux/start-classification-judge.py --seconds 3600
```

该入口仅使用发布记录里登记的组织方实例，覆盖验收时的临时开机命令，启动私有工作端并在指定时间后关机。开赛期间应按运营计划设置时长并留足最后任务完成时间；需要30分钟时限的自测时，不要沿用本轮20分钟验收窗口。已运行的实例不重复开机、不改变当前关机计划。

## 已固定的协议

- 各题3次队伍主动自测，1800 / 3600 / 1800秒总时限；选择相同SHA-256的完成结果正式提交，不重复计次。
- v2表现分公式分别为 `wujie-depth-v1`、`wujie-world-v1`、`wujie-libero-v1`，写入每次测试的私有输入快照，完成后由平台计算。第一阶段实际表现80%、README技术路线20%；PDF论文、消融和深入研究可选，不因未做研究扣技术路线分。最终第一阶段50%、答辩50%。旧机械臂评测器和 `wujie-arm-v1` 继续供历史题目使用。
- 评分项“模型或智能体实际表现”由平台覆盖评委请求中的数字，不能通过手工填分或篡改总分替代可信指标。首次测试后禁止更改公式和评分项权重。
- 比赛配置 `launch.require_ready=true` 时，正式测试先检查起止时间、固定运行环境、匹配在线worker或健康的自动调度池、自动计分、模型额度和已启用资源。缺项不创建测试记录、不扣次数。健康注册GPU池在关机待机时也能接收测试，避免“没有排队无法开机、没有开机无法排队”的循环。
- 管理员检查 `GET /api/manage/competitions/<id>/launch-check`，或在各题“环境与资源”点击检查状态。配置检查通过不等于上游连通验收；须执行以下实际接入。

## 两条智能体赛道

1. Docker可信控制器与独立参赛镜像分离，固定摘要和私有场景在赛前冻结，测试开始后不重新生成。MC公开三档练习种子42/43/44，正式保留原线上三个世界种子，改为600/1500/3000步、空背包、木制/石器/铁器工具链。MC启动使用已预热的Gradle缓存并强制离线，不因SNAPSHOT缓存过期访问外网。
2. v2机械臂使用真正的LIBERO，固定上游提交 `8f1084e3132a39270c3a13ebe37270a43ece2a01`、robosuite1.4.0、MuJoCo2.3.7。三个任务分别为黑碗放盘、字母汤罐入篮、两物品入篮；600/600/1000步，公开初始状态0/1/2，正式使用另一组官方有效初始状态。七维动作和原生 `check_success()` 判定，目标和布局不由选手自报。公开开发包包含本地练习入口、Docker环境、空动作接口示例与官方HDF5最近邻模仿学习入口；不宣称这些接口示例已有任务求解成功率。
3. 绑定真正可用的视觉模型渠道，测试文本和JPEG内联图像请求。为每题配置允许模型、每队Token/调用/费用额度；测评每次最多300调用。开发与测评调用都计入该队该题额度。
4. 通过受控代理在真实Docker中调用上游，验证返回、用量、429、短期令牌过期、非代理外网被阻断。没有真实模型凭据不能用mock结果宣称正式可用。
5. 运行完整三个场景、错误动作与伪造成功负例、总时限终止清理；检查队伍自测、相同ZIP正式选择和评委查看结果。区分接口/传输验收与参赛策略质量。
