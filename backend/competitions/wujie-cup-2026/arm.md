## 任务目标

使用 LIBERO Panda 仿真机械臂，根据自然语言任务与相机画面完成抓取、放置和组合操作。参赛程序通过统一接口控制机械臂。同一轮最终评测使用统一的场景集合、运行预算与原生成功判定。

## 任务范围与场景变化

公开开发环境包含以下三个任务，编号使用官方 `task_order_index=0` 顺序。

| 任务套件 / ID | 操作目标 | 最大控制步数 |
| --- | --- | --- |
| `libero_spatial / 2` | 从桌面中央抓取黑碗，放到盘子上 | 600 |
| `libero_object / 0` | 将字母汤罐放入篮子 | 600 |
| `libero_10 / 0` | 将字母汤罐和番茄酱两件物品放入篮子 | 1200 |

练习配置提供初始状态 0、1、2。队伍可使用公开任务的其他初始状态开展实验。

正式计分包含上述三道公开题与两道双目标组合题。后两题变化包括物体布局与同类操作中的指定物体。每题根据指令完成两件物品的放置。机械臂、相机、观察字段和动作接口与开发环境一致，两个场景独立重置。开发环境提供公开任务的多组初始状态，最终具体布局由组织方保存。五题参考步数依次为300、300、600、700、1100。五题步数上限依次为600、600、1200、1400、2200，均为对应参考步数的两倍。

## 练习材料与环境

[下载 LIBERO 开发包](/downloads/wujie-arm-starter.zip?v=libero-20261018-final-v3)：包含 Agent 接口示例、机械臂动作工具、练习配置、打包与运行脚本。`agent.py` 调用模型选择动作技能，`robot_skills.py` 将技能转换为七维控制。队伍可修改提示词、规划、记忆与技能实现。

[下载配套离线环境](https://github.com/Takamatsu-Hikaru/uestc_ai/releases/download/libero-20261018-final/wujie-libero-practice-20261018-final.tar.gz)，放入解压后的开发包目录。首次运行脚本会自动导入环境，所需场景资源与视频编码器已包含在内。

开发包的 `run.ps1` / `run.sh` 提供容器构建与本地练习入口，`pack.py` 生成提交 ZIP。安装匹配环境后，也可运行 `python practice.py --package agent.zip --scenes practice-scenes.json --output practice-output`。代码、物体资源和初始状态来自 [LIBERO 官方项目](https://github.com/Lifelong-Robot-Learning/LIBERO)，固定提交 `8f1084e3132a39270c3a13ebe37270a43ece2a01`。环境为 Python3.11、robosuite1.4.0、MuJoCo2.3.7、NumPy1.26.4、128×128外部与腕部相机、20Hz控制、CPU无头渲染。练习与测试向 Agent 提供的两路画面均为 128×128；回放另以每路 256×256 录制，合成为 512×256 双视角视频。关闭多重采样、实时阴影和反射，保留物理状态、纹理、相机和原生成功判定。

队伍可使用 LIBERO 公开演示、模型和公开环境生成的数据训练策略，在报告中说明来源。官方模仿学习代码与演示数据下载方法见官方文档。默认选手容器含 NumPy、Pillow、requests，不要求训练模型；需要额外模型依赖、GPU或大权重时须赛前登记，当前 CPU 测评不临时安装依赖。

## 策略与 harness 接口

ZIP 根目录含 `agent.py`、`config.json`。定义 `Agent.act(observation)`，可选 configure 和 reset。`reset(goal)` 接收 `instruction`、`suite`、`task_name`、`max_steps`，不提供测试种子或初始状态编号。

观察提供 `images_jpeg_base64`（外部相机 agentview、腕部相机 robot0_eye_in_hand）、`eef_position`、`eef_quaternion`、`gripper_position`、`joint_position`、`step`、`last_action_valid`、`control`。画面为正向 JPEG。物体真值、奖励和成功标志仅由评测端使用。

执行历史由参赛程序保存，阶段判断与动作调整均基于上述观测。

每次 act 返回原生七维浮点列表 `[dx,dy,dz,rx,ry,rz,g]`，各项有限且在[-1,1]，g=1关闭夹爪，g=-1打开。一次对应一个控制步；非法动作按零位移、零旋转执行，保留上一条夹爪命令，并计入无效动作数。平移为世界坐标系下的相对目标增量，每轴缩放到最多 0.05 米；旋转为相对轴角，每轴缩放到最多 0.5 弧度。实际位移受动力学与碰撞影响，连续返回相同动作会逐步更新目标。`eef_quaternion` 顺序为 xyzw。

模型使用 `model_api.py`。从网站顶部进入「API 平台」(`/api-platform`)，在本队本题的 API 额度中查看允许模型名称，并填写开发包 `config.json` 的 `model`。测评注入 `EVALUATION_API_URL`、`EVALUATION_API_TOKEN`，请求头 `X-Evaluation-API-Token`。当前开发自测的 300 次调用由全部任务共享。模型接入与进程状态的存活范围见 `CONFIG.md`。环境与选手程序处于独立容器，私有场景和结果目录不挂载给选手。

## 提交与运行限制

提交策略或 Agent 代码、配置 ZIP、README 技术路线说明及复现命令。开发包的 `technical-route.md` 提供报告模板，包含方法、输入与常数来源、运行配置、实验结果和团队分工。记录每题完成情况、有效达成步数、模型调用与耗时，并关联实际运行的作品版本。补充 PDF、视频、研究与对照实验可选。

开发自测每队C题3次，每次包含三道公开题，整轮1800秒、最多300次模型调用。最终五题整轮7200秒、最多500次模型调用。选手程序4CPU、2GiB内存，独立LIBERO环境3GiB内存，无GPU；内存为硬上限，选手程序超限会结束该次测试并计次。整组测评容器合计最多6GiB，不使用交换空间；排队不计运行时限。ZIP20MB、最多256文件、解压64MB。公开三题总控制步数上限2400，最终五题合计6000；时限包含初始化、策略和仿真。

本地练习不限次数。平台自测提供开发反馈，正式提交须关联一条已完成的开发自测记录，并使用相同 ZIP。

提交截止后，组织方冻结作品代码、配置、权重及附件，统一运行三道公开题与两道新布局组合题，并核对代码与技术报告。最终评测单独记录作品版本、文件校验值、场景版本和运行预算，不占用队伍自测次数。结果由组织方统一公布，公布后可查看成绩与评测记录。

## 结果与评分口径

可信环境使用 LIBERO 原生 `check_success()` 判分。黑碗放到盘子上的条件为：碗与盘接触、碗中心高于盘中心、两者中心的水平距离小于 3 cm。每个控制步检查一次，全部目标在同一步满足时结束本题；只完成组合题的部分目标时继续运行。系统返回总成功率、各场景结果、控制步数、执行耗时和无效动作。双视角视频连续记录外部与腕部相机，按仿真时间播放；动作轨迹保留执行前后状态、策略等待时间与仿真耗时。

五题参考步数依次为300、300、600、700、1100。

**五题完成分依次为10、10、10、15、15，共60分；效率分共40分，按相同比例分配。** 前三题效率分各为6⅔分，后两题各10分。同题内的多个目标等权，效率按有效达成的累计控制步数计算。正式测评用同一份冻结作品运行五题，五题得分相加得到自动测评成绩。最终成绩为自动测评50%＋技术报告10%＋答辩40%。代码审阅判定通过或不通过；报告考察方案设计、实现与复现、结果与局限分析、引用与团队贡献，权重分别为30%、30%、30%、10%。答辩包含方案介绍、运行演示与现场问答，权重分别为30%、30%、40%。详细公式与边界条件见下列计分规则。同轮所有队伍采用相同场景、参考步数和预算。
