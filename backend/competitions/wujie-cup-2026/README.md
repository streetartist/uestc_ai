# 无界杯赛事筹备包

`overview.md` 保留提案介绍、实施计划、宣传安排、三条赛道、两阶段评分和赛事流程。`classification.md` 补充人体识别赛题的提交与数据准备说明。`backend/build_wujie_competition.py` 将这些内容与现有可信智能体模板组合为三个可导入 ZIP 和一个赛事目录。

赛事与三题均以草稿创建，所有日期为空。未规定队伍规模、奖项分配、渠道、正式数据划分、评分指标换算时，不编造规则。测试配置为筹备值：每队每题3次；MC3600秒、机械臂1800秒、人体识别1800秒，正式开赛前需审定。

第一阶段评审项只有“模型或智能体实际表现”0.8和“研究报告”0.2。题目 `external_weight_percent=50`，确认导入的外部成绩批次用于“现场答辩”；现有合成成绩逻辑会在评委完成第一阶段且答辩成绩确认后，按50/50生成最终成绩。自动指标为评委证据，不把未公布的指标换算或参赛者自报结果当作最终分数。

MC与机械臂沿用已验证的独立容器隔离、可信控制器、指标采集和截止处理。开赛前必须补充模型渠道/额度、重新审定隐藏测试场景并验证基线；机械臂当前支持抓取、放置和堆叠，物体分类与更复杂组合仍是计划扩展。CUHK-X正式数据、授权、类别映射、可信分类镜像尚待接入，不能宣布该题自动评测已就绪。

生成包时传入可信镜像摘要文件，文件键为 `minecraft` 和 `robot-arm`，各含 `controller`、`agent` 摘要。私有种子仅在输出包中随机生成，不写入本目录。包只供管理员导入/导出，不能当选手开发包公开。可通过 `/manage/tracks/<id>/problem-packages` 导入；竞赛目录提供主赛事和三条赛道元数据。

生产渠道密钥、数据集和私有测试包均不得提交仓库。管理员可在“赛事设置”修改完整细则，并在每题“环境配置”调整测试时长、次数、统一API/AutoDL额度与可信环境。

在正确的应用数据库环境中运行 `python backend/build_wujie_competition.py --images <摘要文件> --output <私有目录>`，再运行 `python backend/install_competition_bundle.py <私有目录> --credentials <管理员凭据文件>`。导入器经过管理员登录及现有API校验，重复运行保留已有赛事、赛道、题目与设置，只补充缺失项；不会发布、建队、运行容器或创建收费实例。生产环境在首次导入前执行数据库备份。
