# 比赛 API 平台

入口为前端 `/api-platform`。界面复用本站的颜色、导航、表单、登录会话与赛事队伍；参考 [ZenAPI](https://github.com/streetartist/zenapi) 的渠道、模型、令牌和用量工作流，在 Flask 内独立实现，不另建一套用户系统。

## 使用顺序

1. 在服务器 `.env` 设置独立随机 `AI_GATEWAY_ENCRYPTION_KEY`，然后升级数据库：`python -m flask --app backend/app.py db upgrade`。该密钥必须稳定保管；更换后旧上游密钥无法解密，需要重新填写。加密使用 Fernet，并与会话密钥分离。
2. 管理员在「API 平台 → 渠道管理」填入 API 基址、上游密钥和模型。每行一个密钥；编辑时留空保留，填写则替换全部密钥。OpenAI / Anthropic 基址包含 `/v1`；自定义渠道填写完整 POST 地址。HTTPS 是默认要求，本地回环模型服务可以显式设置 `AI_GATEWAY_ALLOW_LOCAL_HTTP=1`。
3. 可检测连接并导入发现的模型，也可手工设置 `展示模型名=上游模型名`。点击模型可以启用／停用。优先级高的渠道优先；同优先级按权重选择。渠道失败后，仅对明确拒绝的 401 / 403 / 404 / 429 响应尝试另一密钥或渠道，最多 8 次。连接中断、超时、服务端错误可能已产生用量，保留预占额度并记录错误，不盲目重发。
4. 管理员或组织者从「赛事管理 → 编辑题目 → API 额度」设置本题统一额度：每队授权模型、允许渠道、总调用次数、总 token、单次最大输出、每分钟调用次数、同时调用数量及可选费用额度。所有队伍使用相同配置，各队分别计量；保存时同步现有队伍，之后新建队伍自动获得本题额度，没有队伍也能先保存。修改额度保留旧密钥和各队已用量；任何队伍已用量超过新上限时拒绝整次修改，避免部分队伍更新。配置统一额度后，旧逐队题目修改接口返回 409，保持一致。新建题目需先保存再配置额度。原有通用额度在「API 平台 → 通用额度」配置，兼容旧数据；题目设置与额度设置各自保存。费用按管理员填写的“点数 / 百万 token”统计，默认单价为 0，不代表实际商业付款。没有使用时长额度或密钥到期时间。
5. 队伍成员选择“题目 × 队伍”的配额创建密钥，保存一次性显示的完整密钥。同一配额的所有成员、密钥与对应自动评测共用额度；不同题目互不扣减。普通开发调用按所用密钥归属记账，聊天内容本身不能证明实际用于哪个题目；正式评测按任务真实 `problem_id` 选择配额。成员离队后，其创建的密钥无法继续使用；队伍其他成员可以停用旧密钥。管理者可以统一停用本题 API；旧的逐队题目额度在保存本题统一额度之前保持原配置。
6. 在模型广场查看模型，在对话测试里粘贴密钥验证真实流式调用。在调用记录中筛选、分页或导出 JSON；评委仅能查看已分配赛事的队伍用量。

## 兼容接口

| 路径 | 功能 |
| --- | --- |
| `GET /api/ai/v1/models` | 密钥授权范围内的启用模型 |
| `POST /api/ai/v1/chat/completions` | OpenAI Chat，支持 SSE；Anthropic 渠道转换文本、图片及工具调用 |
| `POST /api/ai/v1/responses` | Responses，转发到 OpenAI 兼容渠道，支持 SSE |
| `POST /api/ai/anthropic/v1/messages` | 原生 Anthropic Messages，支持 SSE |

OpenAI 兼容 SDK 的 `base_url` 为 `http://127.0.0.1:5000/api/ai/v1`（部署时换成真实 API 域名）；请求头 `Authorization: Bearer sk-contest-...`。原生 Anthropic 也支持 `x-api-key`。管理接口沿用本站 HttpOnly 登录会话，API 密钥无法管理渠道、队伍或评测任务。

```json
{
  "model": "组织方授权的模型名",
  "messages": [{"role": "user", "content": "你好"}],
  "max_tokens": 256,
  "stream": true
}
```

密钥只存 SHA-256 散列；上游密钥只存密文，不返回给选手或浏览器。日志不记录提示词、回答内容或密钥；代理禁止携带上游凭据跟随重定向。自定义渠道按原请求结构转发，需提供可识别的 OpenAI 用量字段。

## 配额结算与边界

- 每次派发前，数据库原子更新共享调用次数、token 与可选费用预占；并发请求不能各自读取旧余额绕过限制。正式评测请求还在同一事务内检查并增加任务调用次数。管理员增加总额度时保留原用量，不会重置选手记录。
- 文本、内联图片和工具定义使用请求字节数加消息封装余量预留输入 token，每张图片额外预留 32,768 token，再加输出上限。同一请求只允许一种与接口对应的输出限制参数，避免不同供应商使用不同字段绕过上限。预占是保守边界，接近额度时可能需调低单次输出或补充配额；最终 token 来自上游实际 `usage`，不是预估数字冒充实测。
- 图片使用内联 base64 / data URL。计量模式不接受远程图片、托管文件／工具、后台 Responses、历史响应 ID 或会话引用，以免输入用量无法预留。支持选手自行执行的函数工具。请求最多 4 MiB，响应最多 16 MiB。HTTP 有 120 秒故障超时，用于终止失联请求，不是选手使用时长限额。
- Chat 流式请求自动带 `stream_options.include_usage=true`。Responses 在 `response.completed` 读取用量。Anthropic 合并开始和结束事件，并计入缓存创建／读取的输入用量。流结束并确认后，释放多余预占；输入、输出、缓存 token、参考费用、延迟、首次事件延迟和渠道尝试均可查。
- 上游缺失用量、生成中断或客户端断开时保留预占，标记“用量待确认”。进程崩溃留下的记录在超过故障期限后，由概览／日志读取转为同一状态，额度仍然保留。组织方核对后可增加总配额；没有无证据自动退还额度的通道。
- 若上游报告用量超过预占并超出队伍额度，保留真实用量、自动停用队伍。严格 token 边界依赖受信任上游按声明的输出上限返回正确用量；不可信供应商不可用于正式比赛。
- 部署采用 PostgreSQL；原子配额更新和日志同事务提交。SQLite 用于本地验证。迁移 `d8a2f19c630e` 仅创建四张新表，不修改原有作品版本约束。`e9c3a72b108f` 增加题目范围，原有配额保留为通用配额，旧密钥、用量和额度不变；唯一约束保证每队每题只有一份配额、每队只有一份通用配额。存在题目配额时拒绝向旧版降级，避免合并用量或扩大旧密钥权限。`f1d4b83c219a` 增加统一题目策略表，旧队伍记录保留不变；配置统一策略后拒绝有损降级，避免后续队伍丢失配额。统一保存和队伍创建使用同一赛事数据库锁，避免并发首次配置与创建队伍时漏发额度。

## 评测复用

通用 `/api/evaluation-worker/runs/<id>/api` 优先使用该队伍该题的配额；没有单独配额时才使用队伍通用配额。题目配额耗尽或被停用时直接拒绝调用，不回退到通用配额或旧固定上游。日志标明所属配额的题目并关联 `evaluation_run_id`。参赛容器仍使用单任务调用令牌，不能获得工作进程租约。完全未分配新平台配额的旧任务继续兼容 `EVALUATION_API_URL` / `EVALUATION_API_KEY` 固定上游方式。比赛正式启用前应为所有队伍配置配额，运行端出口限制沿用现有评测部署要求。
